# sayyes.me

거절 버튼이 도망가는 링크를 만들어 보내는 웹 앱.

'싫어'를 누르려 하면 버튼이 도망간다. 몇 번을 눌러도 안 눌린다.

## 페이지

| 파일 | 역할 |
|---|---|
| `index.html` | 소개 페이지. 자동 재생 데모가 돌고, 화면을 탭하면 직접 조작으로 전환된다 |
| `make.html` | 링크 만들기. 질문·버튼 문구·도망 문구·색을 정하고 링크를 복사한다 |
| `p.html` | 받는 사람이 여는 화면 |
| `config.js` | 기본값·프리셋·검사 규칙·도망 위치 계산 (세 페이지 공용) |

빌드 과정이 없다. 정적 파일을 그대로 올리면 동작한다.

## 내용을 담는 방식

링크 내용은 전부 URL에 실린다. 링크를 여는 데 서버가 필요 없다는 뜻이다.

```
p.html?d=<base64url(JSON)>
```

기본값과 같은 항목은 URL에서 빠지므로, 조금만 고친 링크는 짧게 유지된다.

## 도망 위치 규칙

`config.js`의 `pickSpot()`이 세 가지를 지킨다.

1. **'응' 버튼을 절대 가리지 않는다** — 회피 대상 사각형으로 넘겨서 겹치는 후보를 탈락시킨다. 커진 상태가 그대로 반영된다
2. 포인터에서 충분히 멀되, **지금 자리에서 가장 가까운 곳**으로 간다. 구석으로 순간이동하면 금방 질린다
3. 화면 밖으로 나가지 않는다. 랜덤 후보가 전부 막히면 격자로 훑어 확실히 찾는다

모바일에는 hover가 없으므로 '누르려는 순간' 도망치는 것이 본체다. 마우스 근접 회피는 데스크톱에만 얹혀 있다.

## 로그

내용이 URL에 있어서 **한번 퍼진 링크를 나중에 내릴 방법이 없다.** 신고가 들어와도 무슨 내용이었는지 알 수 없으면 대응할 수가 없다. 그래서 **만들어진 내용과 열린 내용을 기록한다.**

- 기록 대상: 질문, 받는 사람, 보낸 사람, 버튼 문구, 도망 문구, 도망 횟수
- 기록 위치: Google 스프레드시트 (`collector/apps-script.gs`)
- **이 사실을 만들기 화면과 여는 화면 양쪽에 표시한다.** 몰래 모으지 않는다

`stats.js`의 `ENDPOINT`가 비어 있으면 아무것도 전송하지 않는다.

## 내용 검사

기록과 별개로, 화면을 그리기 전에 내용을 검사한다. 주소창을 직접 고쳐도 이 검사를 지나가야 한다.

- 주민등록번호 · 카드번호 · 전화번호 · 계좌번호 · 이메일 · 상세주소가 보이면 화면을 띄우지 않는다
- 길이를 강제로 자른다 (질문 60자, 문구 40자, 30줄)

### 막지 못하는 것

- **모욕적인 표현.** 자연어라 사전으로 못 거른다. 우회가 쉽고 오탐이 많아 넣지 않았다
- **이미 퍼진 링크의 무효화.** 로그로 내용은 확인할 수 있지만, 링크 자체를 죽일 수단은 없다. 내용이 URL에 들어 있기 때문이다. 해결하려면 링크에 짧은 ID만 싣고 내용은 별도 저장소에 두어야 한다
- **받는 사람의 탈출구.** 거절 버튼이 안 눌리는 구조는 괴롭힘에 쓰일 수 있다. 아직 넣지 않았다

## 로컬에서 보기

```
python -m http.server 8080
```

`file://`로 열어도 동작하지만, 모바일 확인은 서버로 띄워 같은 네트워크에서 접속하는 편이 낫다.
